# kfootball-lab

K리그 데이터로 **블로그 글 + 분석 웹사이트**를 만드는 개인 프로젝트.

한 번 실행하면 이 세 가지가 한꺼번에 나옵니다.

```
데이터(CSV) → 분석 → ① 차트 PNG  ② 웹사이트 데이터  ③ 블로그 글 초안
```

---

## 0. 처음 한 번만 (약 15분)

### ① Python 설치 확인

Windows에서 `Win + R` → `cmd` 입력 → 아래를 치세요.

```
python --version
```

`Python 3.11.x` 처럼 나오면 됩니다. "명령을 찾을 수 없습니다"가 나오면
[python.org](https://www.python.org/downloads/)에서 설치하세요.
설치 화면에서 **"Add Python to PATH"** 체크를 꼭 하세요.

### ② VS Code에서 폴더 열기

1. VS Code 실행
2. `파일` → `폴더 열기` → 이 `kfootball-lab` 폴더 선택
3. 위쪽 메뉴 `터미널` → `새 터미널` (단축키 ``Ctrl + ` ``)

### ③ 필요한 라이브러리 설치

터미널에 그대로 입력하세요.

```
pip install -r requirements.txt
```

### ④ 실행

```
python run.py
```

`완료!` 가 뜨면 성공입니다.

- `output/charts/` → 차트 PNG (블로그에 붙여넣을 것)
- `posts/` → 블로그 글 초안 (해석을 직접 채워 넣을 것)
- `site/index.html` → **더블클릭**하면 브라우저에서 사이트가 열립니다

> 지금 보이는 숫자는 전부 **샘플(가짜)**입니다. 파이프라인이 도는지 확인용입니다.

## 1. 실제 데이터로 바꾸기

`data/raw/` 안의 CSV 네 개를 직접 만든 것으로 바꾸면 됩니다.
**컬럼 이름만 똑같이 맞추면** 나머지 코드는 손댈 필요가 없습니다.

| 파일 | 한 줄 = | 필수 컬럼 |
|---|---|---|
| `matches.csv` | 경기 한 개 | match_id, date, round, home_team, away_team, home_score, away_score |
| `lineups.csv` | 경기 × 선수 | match_id, player, position, started(1/0), minutes |
| `team_match_stats.csv` | 경기 × 팀 (양 팀 모두) | match_id, team, goals, pass_att, pass_cmp, shots, shots_on, tackles, interceptions, blocks, clears, fouls, corners |
| `player_match_stats.csv` | 경기 × 선수 | match_id, player, pass_att, pass_cmp, key_pass, shots, goals, assists, tackles, interceptions, duels_won |
| `team_season_stats.csv` **(선택)** | 팀 (시즌 누적) | team, matches, goals, goals_against, points, pass_att, pass_cmp, shots, shots_on, tackles, interceptions |

### `team_season_stats.csv`가 왜 필요한가 (승격 경쟁 분석의 핵심)

대구 경기를 아무리 많이 입력해도, **대구와 만나지 않은 경기의 경쟁팀 기록은 알 수 없습니다.**
그래서 이 파일 없이 팀 비교를 하면 상대팀은 "대구전 표본"만 반영되어 왜곡됩니다.

데이터포털의 **'팀 기록'** 화면을 보고 **팀당 한 줄씩만** 옮겨 적으세요.
K리그2 13개 팀이면 20분 정도이고, **한 달에 한 번만 갱신해도 충분합니다.**

`data/raw/team_season_stats.csv.예시` 파일을 복사해서
`team_season_stats.csv` 로 이름을 바꾸고 채우면 됩니다.
파일이 있으면 자동으로 감지되어 승점·득실차 컬럼까지 표에 나타납니다.

### 입력 요령 (중요)

- **엑셀로 열어서 편집하고 CSV로 저장**하면 가장 편합니다.
- 한 경기당 입력은 5~10분 정도입니다. **경기 직후 바로 입력하는 습관**을 들이세요.
  몰아서 하면 절대 못 합니다.
- `team_match_stats.csv`는 **상대 팀 기록도 함께** 넣어야 합니다.
  압박 지표(상대 패스 성공률)를 계산하는 데 쓰입니다.
- 모든 파일의 `match_id`가 **정확히 같아야** 연결됩니다. (예: `2026-01`)
- 출처와 수집일을 메모해 두세요. 글에 반드시 표기해야 합니다.

### 데이터를 어디서 구하나

1. **지금 (인증키 없이)** — [K리그 데이터포털](https://data.kleague.com/) 화면을 보고 직접 입력
2. **나중에** — [K리그 API](https://api.kleague.com/) 인증키를 받으면 `src/load.py`의
   `_read_csv` 부분만 API 호출로 바꾸면 됩니다. 다른 파일은 그대로입니다.
3. **연습용** — [StatsBomb 오픈 데이터](https://github.com/statsbomb/open-data) (해외, 무료)

> ⚠️ 자동 수집(크롤링)은 사이트 이용약관을 먼저 확인하세요.
> 한 시즌 36경기는 손으로 입력해도 충분합니다.

## 3. 무엇을 분석하나

### On/Off 분석 (이 프로젝트의 핵심)

특정 선수가 **출전한 경기**와 **결장한 경기**로 나눠 팀 기록을 비교합니다.
데이터포털에는 없는, 직접 계산해야 나오는 지표라서 차별점이 됩니다.

```
python run.py 세징야
python run.py 한국영
```

**반드시 같이 써야 하는 한계**

- 표본이 작습니다. 결장 경기가 3~4경기면 우연일 수 있습니다.
- 상대 팀 전력과 홈/원정이 섞여 있습니다.
- 다른 선수가 같이 빠졌다면 누구의 영향인지 구분되지 않습니다.

→ **"이 선수 덕분이다"가 아니라 "이런 경향이 보인다"**로 쓰세요.
표본이 작으면 프로그램이 자동으로 경고를 붙여줍니다.

### 압박 지표 (PPDA)

정식 지표 **PPDA**(Passes Per Defensive Action)는 이렇게 계산합니다.

```
PPDA = 상대가 자기 진영+중앙(60% 구역)에서 시도한 패스 수
       ÷ 우리 팀이 그 구역에서 한 수비 액션 수(태클+인터셉트+파울+클리어링)
```

낮을수록 강한 전방 압박(4~5), 높을수록 물러서는 로우 블록(15~20)입니다.

**자주 도는 오해:** "PPDA는 좌표 없이 계산할 수 있다"는 말은 **절반만 맞습니다.**
전체 x,y 좌표는 필요 없지만, **이벤트를 구역별로 나눈 집계**는 반드시 있어야 합니다.
경기 전체 합계만으로는 계산할 수 없습니다.

그래서 이 프로젝트는 두 단계로 동작합니다.

| 가진 데이터 | 계산되는 것 |
|---|---|
| 경기 전체 합계만 (지금) | **대체 지표** — 상대 패스 성공률, 팀 수비 액션 합계 |
| 구역별 집계가 생기면 | **정식 PPDA** + 점유율 보정 PPDA + 필드 틸트 |

구역별 데이터가 생기면 `team_match_stats.csv`에 아래 컬럼만 추가하세요.
코드는 자동으로 감지해서 PPDA를 계산합니다.

| 선택 컬럼 | 뜻 |
|---|---|
| `opp_pass_att_def60` | 상대가 자기 진영+중앙에서 시도한 패스 수 |
| `def_action_att60` | 우리 팀이 그 구역에서 한 수비 액션 수 |
| `possession` | 점유율(%) — 보정 PPDA 계산용 |
| `pass_att_final3` | 공격 진영 패스 시도 (양 팀) — 필드 틸트용 |

**PPDA의 한계도 같이 쓰세요.** 압박을 '시도'한 횟수만 셀 뿐 실제로 공을 뺏었는지는
반영하지 않습니다. 또 점유율이 높은 팀은 분모가 작아져 PPDA가 실제보다 높게
(=약한 압박처럼) 보입니다. 한계를 아는 것 자체가 실력입니다.

## 4. 블로그에 올리는 순서

1. `python run.py` 실행
2. `posts/`의 `.md` 파일을 열어 `[직접 작성]` 부분을 채움
3. `output/charts/`의 PNG를 네이버 에디터에 붙여넣기
4. 기존 `blog-automation` 파이프라인으로 발행
5. `git push` → GitHub Pages 사이트도 자동 갱신

> **원칙: 숫자와 차트는 자동, 해석과 의견은 사람이 직접.**
> 구단이 보는 것은 "이 사람이 숫자를 어떻게 읽는가"입니다.

## 5. GitHub에 올리기

```
git init
git add .
git commit -m "첫 커밋: 분석 파이프라인과 사이트"
git branch -M main
git remote add origin https://github.com/<아이디>/kfootball-lab.git
git push -u origin main
```

GitHub 저장소 → `Settings` → `Pages` → Source를 `main` 브랜치 `/ (root)`로 설정하면
`https://<아이디>.github.io/kfootball-lab/site/` 에서 사이트가 열립니다.

### 저작권 주의

- 선수 **사진**과 구단 **엠블럼**은 쓰지 마세요. 이름과 등번호만 씁니다.
- 경기 **영상**도 쓰지 마세요. 직접 그린 전술 다이어그램으로 대체합니다.
- 데이터 **출처와 수집일**을 모든 글과 사이트에 표기하세요.

## 7. 자주 나는 오류

| 증상 | 원인과 해결 |
|---|---|
| 차트 한글이 □□□ | 한글 폰트 없음. Windows는 대개 자동 해결. 안 되면 나눔고딕 설치 |
